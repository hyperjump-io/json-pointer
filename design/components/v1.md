# What changed from v1

The API is the same shape. These are the differences, and why.

| Change | Breaking? | Why |
| --- | --- | --- |
| The functions and the curried function types start with `pointer` (`get` is `pointerGet`, `Getter` is `PointerGetter`) | Yes | [Naming](naming.md) |
| `nil` is removed | Yes | `""` is shorter and says the same thing ([Naming](naming.md#nil)) |
| Array segments must be `0`, `[1-9][0-9]*`, or `-` | Fixes a bug | `parseInt` read `/01` and `/1x` as item 1 ([Pointers](pointers.md#array-indexes)) |
| Non-index segments on arrays throw | Yes, for `pointerSet`/`pointerAssign` | JSON can't hold them ([Don't lose data silently](../principles/dont-lose-data.md)) |
| `__proto__` is an own property | Fixes a bug | [Changing values](changing-values.md#__proto__) |
| `pointerUnset` returns `subject` when there's nothing to remove | Rarely | [Changing values](changing-values.md#copying) |
| Curried functions parse when created | Only for invalid pointers | [Currying](currying.md) |
| Functions take segments as well as strings, and `pointerParse`/`pointerStringify` are exported | No | [Pointers](pointers.md#segments-as-a-pointer) |
| `pointerSegments` is removed | Yes | `pointerParse` replaces it ([Pointers](pointers.md#segments-as-a-pointer)) |
| The curried form is chosen by argument count | Only for `pointerGet(pointer, undefined)` and the like | [Currying](currying.md) |
| Errors are classes, and the invalid pointer's message includes the pointer | Only for code that matches the message exactly | [Errors](errors.md) |

[Migrate from v1](../../website/migrate-from-v1.md) lists only the
deliberate breaking changes, not the rows marked "Fixes a bug". v1 can
still fix those bugs, and then what the guide said about v1 would be
wrong. Rejected: listing the bug fixes too, as things that can break code
that relied on them.
