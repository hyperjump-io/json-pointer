# What changed from v1

The API is the same shape. These are the differences, and why.

| Change | Breaking? | Why |
| --- | --- | --- |
| Array segments must be `0`, `[1-9][0-9]*`, or `-` | Fixes a bug | `parseInt` read `/01` and `/1x` as item 1 ([Pointers](pointers.md#array-indexes)) |
| Non-index segments on arrays throw | Yes, for `set`/`assign` | JSON can't hold them ([Don't lose data silently](../principles/dont-lose-data.md)) |
| `__proto__` is an own property | Fixes a bug | [Changing values](changing-values.md#__proto__) |
| `unset` returns `subject` when there's nothing to remove | Rarely | [Changing values](changing-values.md#copying) |
| Curried functions parse when created | Only for invalid pointers | [Currying](currying.md) |
| Functions take segments as well as strings, and `parse`/`stringify` are exported | No | [Pointers](pointers.md#segments-as-a-pointer) |
| `pointerSegments` is removed | Yes | `parse` replaces it ([Pointers](pointers.md#segments-as-a-pointer)) |
| The curried form is chosen by argument count | Only for `get(pointer, undefined)` and the like | [Currying](currying.md) |
| Errors are classes, and the invalid pointer's message includes the pointer | Only for code that matches the message exactly | [Errors](errors.md) |
